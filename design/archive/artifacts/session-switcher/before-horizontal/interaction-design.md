# 最近会话切换 · 设计草案

日期：2026-10-17。阶段：交互设计与本地原型，待用户确认后接入实际插件。

预览：<http://127.0.0.1:4381/artifacts/session-switcher/index.html>

## 目标与视觉

让用户在手头几个会话之间快速往返。快捷键在当前 DSH 窗口内切换会话，不影响后台任务执行。采用窗口中部的紧凑浮层，宽度 520 px，沿用当前 DSH 的中性灰、明暗主题和轻蓝选中态。

最近 5 个会话包含当前会话，按实际查看顺序排列，跨工作区但不跨窗口或 Host。每行展示标题、工作区及可获取的运行状态；当前会话标记“正在查看”。标题过长省略，完整标题可由鼠标悬停和辅助技术读取。第一版采用列表，便于辨认文字相似的会话，避免为展示候选加载所有会话内容或捕获屏幕。

参考：[Dia Quick Switch 官方说明](https://www.diabrowser.com/release-notes/1-33-0-tab-performance)、[Dia 1.51.0 官方更新](https://www.diabrowser.com/changelog/mac/1-51-0)。最近 5 项来自此参考；列表外观、140 ms 延迟和焦点规则是本项目提案，不声称复刻 Dia 的内部参数。

## 键盘协议

| 输入 | 行为 |
| --- | --- |
| Ctrl + Tab 快按并松开 | 立即打开上一个访问的会话，浮层来不及显示；再次快按可以往返 |
| 按住 Ctrl 后按 Tab | 冻结本次最近列表，预选上一个会话；约 140 ms 后显示浮层 |
| Ctrl 保持按住，继续按 Tab | 向更早的候选移动，最后一项之后循环到当前会话 |
| Ctrl + Shift + Tab | 反向移动；首次反向唤起从最近列表的末项开始 |
| 松开 Ctrl | 打开选中的会话，关闭浮层；只执行一次切换 |
| Esc | 取消本次挑选，恢复原会话和原焦点；即使 Ctrl 还按着也可取消 |
| Enter / 点击某行 | 提前确认并结束本次挑选；随后 Ctrl 松开不再重复执行 |
| 方向上下键 | 浮层内辅助选择 |
| 窗口失活 / 页面隐藏 | 取消挑选，不确认后台候选 |

按住 Tab 的自动重复事件不连续滚动。单次 Tab 的按下、松开都保持在本次手势里，不把 Tab 交给底层输入框。Esc 仅关闭这一层，不能继续触发导航返回或停止生成。

## 状态与边界

- 候选移动只修改高亮。只有确认打开目标后才更新最近顺序。鼠标打开会话、搜索打开、新建以及原有 `g a` 都进入同一最近记录。
- 后台回复、完成通知、时间戳变化和列表重排不算访问，也不改变正在挑选的顺序。状态标签可更新。
- 最近记录以会话 ID 去重，初始仅加入实际显示的当前会话；没有历史时不伪造“最近”。第一版以当前窗口生命周期为范围，重载延续可考虑 sessionStorage；重启恢复不是原型已实现能力。
- 排除已删除、已归档及当前无权打开的会话；空白新会话只有当前正在使用时可作为返回项。确认前重验目标，失效则取消并留在原会话，不擅自跳到旁边一项。
- 少于两个有效会话时不显示空切换器。插件端可用一次简短反馈说明没有其他最近会话。
- 取消恢复原输入框、文本选区和滚动位置；后台生成继续。确认后沿用当前插件的自动导航设置，不让选择时的 Tab 或 Enter 落入终端、网页或发送按钮。
- 现有弹窗、菜单、快捷键录制及输入法组合优先。切换器打开后，阻止背景导航按键，鼠标悬停不改变键盘候选，点击外部取消。
- 原有 `g a` 保留为导航态下的快速往返入口，与新切换器使用同一访问顺序。

## 接入依据与实施顺序

当前项目为 `dsh-magic-shortcuts@0.1.10`。本轮读取了 `src/client.js` 的会话订阅、返回导航和 `previousSession` 分支，并从当前安装的官方 `app.asar` 中只读提取了 shortcuts、ui-workspace、session-controller 的客户端和 README。

1. 提取独立的最近顺序和挑选状态机，替代只记录 previousSession 的方式。候选对象只持有 ID 与列表元数据；不 retain 或打开候选会话正文。
2. 通过官方快捷键服务注册正向、反向入口；利用现有 shell.overlay 绘制浮层，确认时调用已有 `uiWorkspace.openSession()`。
3. 在隔离 DSH 中先验证组合键唤起和 Ctrl 松开。官方可配置快捷键通过原生桥接执行；公开 `observeFixedInput` 面向局部处理后的 DOM 按下或 reset，未提供完整修饰键松开订阅。因此，不能把普通网页的 keyup 验证当成真实 DSH 的可行性证明。
4. 优先验证“唤起时将焦点交给插件浮层，随后由 shell 收到 Ctrl 松开”这条最小路径，覆盖聊天输入、终端、内嵌网页、快速松开、失焦和重复按键。原生拦截与焦点交接之间的竞态必须实测。
5. 若这条路径不能可靠支持快速按放，需要明确宿主的按键生命周期接口缺口，再给出范围与成本；不能改为每按一次就打开一个会话，却仍称为相同交互。
6. 通过后接入会话元数据及失效处理，验证草稿、原有快捷键和插件卸载，再准备实际插件给用户体验。

## 本轮原型范围

`index.html` 是原有演示页面的独立副本，`switcher.js` / `switcher.css` 仅用于本地设计展示；没有改动 src、lib、安装包或已安装 DSH。会话与状态为原有示例数据及演示状态，不读取真实聊天。

浏览器可能保留 Ctrl + Tab 自己使用，因此额外提供“体验切换器”和“快速往返”按钮。“模拟按住 Ctrl”工具条仅存在于原型：Tab / Shift + Tab、方向键、Enter、Esc 也可完成体验；这些按钮不属于拟实现的正式产品。

验证结果见 [design-qa.md](design-qa.md)。
